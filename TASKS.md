- 2026-10-17 · upsert semantics · `upsert_photos` keys on `(folder_id, file_name)`, never overwrites starred/rating/hidden/caption/edit_version, fills an empty caption from `import_caption`, and nulls `content_hash`/`phash` when `quick_key` changed.

- 2026-10-17 · albums · `move_in_album(album, photo, before)` changes only the moved row (midpoint of its new neighbours, `first - 1.0` at the front, `last + 1.0` at the end) and renormalizes the whole album to `1.0, 2.0, ...` once any neighbouring gap is below 1e-9.
- 2026-10-17 · write transactions · `Catalog::write_tx` uses `BEGIN IMMEDIATE`. With the default DEFERRED behaviour `writer_serializes_concurrent_writes` failed ~3% of runs with an instant `database is locked` (a read-then-write upgrade is not covered by the busy handler); 150/150 pass after the change.
- 2026-10-17 · FTS schema V2 · SPEC §5.2's `content=''` table cannot DELETE or replace rows (needed for incremental updates), so V2 (append-only, V1 untouched) recreates it with `contentless_delete=1` (bundled SQLite is 3.53.2). Column set and tokenizer are unchanged.
- 2026-10-17 · FTS maintenance style · explicit Rust calls in each mutator inside the same transaction, not triggers, except the delete trigger (which also covers FK cascades from folders and roots). Columns: `camera` = `"<make> <model>"` trimmed, `people` = distinct names of people linked via faces, `album_names` and `tags` space-joined in name order. Future writers (folder rename M6.5, faces/people M9) must call `fts::refresh_photos`; the random-op equality test is the safety net.
- 2026-10-17 · set_caption · added `Catalog::set_caption(ids, Option<String>)` (stores verbatim; the 2000-char rule from §6.7.1 belongs to the service layer in M6) because the M1.4 acceptance test needs a caption change path.
- 2026-10-17 · backups · rusqlite gets the `backup` feature (same crate, no new dependency). Backups are named `catalog-YYYY-MM-DD.sqlite3`, one per day (an existing file for the day is never overwritten), and only files matching that exact name are rotated or deleted. The caller (app startup, M-later) supplies `today` so tests stay deterministic; stale `catalog-*.sqlite3.tmp` files are cleaned up.
- 2026-10-17 · restore · the damaged database is kept as `<catalog>.corrupt` (+ `-wal`/`-shm`), replacing any earlier `.corrupt`, so stale WAL frames cannot be replayed onto the restored file and the user can still inspect or recover the old data. Restoring requires that the catalog is not open.
- 2026-10-17 · shutdown · `Catalog` drop closes the read-only connections before the writer; otherwise a read-only connection closed last leaves `-wal` behind and the `.sqlite3` file alone lacks recent data (found while writing the corruption tests).
- 2026-10-17 · workspace deps · only crates needed soon are listed (exact `=` pins); others (notify, gpui-kit, nom-exif, ...) are added with the task that first uses them.
- 2026-10-17 · JPEG decoding · `lb-media` decodes JPEG with `jpeg-decoder` 0.3.2 (not `image`/zune-jpeg) because it offers real DCT scaling (`scale()`) and errors on truncated streams, which zune-jpeg silently accepts (see the truncated-JPEG decision above). Everything else goes through `image`.
- 2026-10-17 · format identification · files are identified by magic bytes, not extension (a PNG named `.jpg` decodes as PNG); extension mapping (`format_for_extension`) is only used to decide what to index. `3gp` and `mts` map to `Format::Mp4` because `Format` has no variant for them.
- 2026-10-17 · truncation detection · `probe` rejects JPEGs without an `FFD9` marker in their last 64 KiB and PNGs without `IEND` (cheap structural check, no pixel decode), so the scanner can mark truncated files unreadable within the metadata-only scan budget; other formats rely on the header read plus decode.
- 2026-10-17 · `decode(path, max_long_edge)` semantics · the result's long edge is exactly `max_long_edge` when the source is larger (DCT-scaled decode, then a Lanczos3 `resize_exact`), never upscaled; orientation is applied last.
- 2026-10-17 · EXIF reader · production code uses `kamadak-exif` 0.6.1 (the SPEC's fallback) rather than `nom-exif`: it is already pinned and exercised by the fixture tests, supports JPEG/PNG/WebP/TIFF/HEIF containers and needs no extra dependency. Offsets (`OffsetTimeOriginal`) are exposed in `ExifData::offset` but `taken_at` stays naive local time, as SPEC §6.2.2 says.
- 2026-10-17 · mtime to taken_at · file mtime converts to naive local time with `chrono::Local`; callers pass unix seconds (`fallback_taken_at`) so tests compare against the same conversion rather than a hard-coded zone.
- 2026-10-17 · quick_key · for files of at most 128 KiB the head and tail would overlap, so the tail is only the part not already hashed as head; this keeps the key a pure function of file bytes and `quick_key_of_bytes` identical to the file version.
- 2026-10-17 · scan skip rules · the hidden/system-name rule applies only to entries *below* a root (a root itself may be a dot-directory such as a `tempfile` dir); every dot-prefixed name is ignored, which covers `.Trash*` and `.picasaoriginals`; the Windows hidden attribute is checked for files only.
- 2026-10-17 · folders · `folders` rows are created only for directories that contain at least one indexed file, plus their ancestors up to the root directory (so `parent_id` chains are complete). A nested root's own scan reassigns `root_id` of its folders (`ensure_folder` upserts).
- 2026-10-17 · scan phases · the walk collects all candidates first so `total_estimate` is exact; unchanged files count as done immediately. A final forced `Progress` (done == total) precedes `Finished`. Cancellation is checked between batches and before missing-detection; a cancelled scan never marks rows missing.
- 2026-10-17 · scan row semantics · `updated` counts changed files that already had a row; `errors` counts unreadable files (once, when first indexed or changed) plus walk errors; videos are not decoded yet and are handled in M10.2.
- 2026-10-17 · path comparison · normalized root paths are compared exactly (no lower-casing key column): `canonicalize` returns the on-disk spelling, which makes comparisons stable on case-insensitive volumes for existing paths. Revisit only if a test needs two spellings of one root.
- 2026-10-17 · exclude semantics · adding or switching a root to `exclude` deletes the folders under its path (cascading photos/albums links/tags) regardless of which root owned them, then rescans any nested non-excluded roots so they survive; the exclude root row stays as a marker so ancestors skip the subtree.
- 2026-10-17 · notify versions · `notify` 8.2.0 + `notify-debouncer-full` 0.6.0 (latest stable pair; 9.0/0.8 are release candidates). CC0-1.0 (notify) is already allowed in deny.toml.
- 2026-10-17 · watcher scheduling · paths from debounced events enter a pending map with a stat snapshot; after `settle` the snapshot is compared with a fresh stat and the path is re-queued if it changed (in-progress copy), otherwise it is synced. Access events other than close-after-write are ignored. Watcher tests use 50 ms debounce / 20 ms settle; only `folder_manager_watch_scans_and_watches` uses the SPEC defaults.
- 2026-10-17 · move window · SPEC §6.3.2 says a vanished file is a move only if an identical one appears within 5 s. Implemented as a superset: deletions mark rows missing immediately and any later new file with the same `quick_key` and size relinks a missing row, whenever it appears (also in full rescans, as the second sentence of §6.3.2 requires). Missing rows are hidden by default and removal is manual, so late relinking cannot lose data; a *copy* (original still present) never relinks.
- M4.1: Job queue uses std worker threads + a `BTreeMap<(Priority, seq)>` rather than rayon, because rayon has no priorities. Coalescing applies to queued and running jobs (and raises priority of the existing queued job). Dropping the queue cancels pending jobs and joins workers.
- M4.2: Access index stores a monotonically increasing logical tick per key (persisted in `thumbs/access.idx`, flushed on GC/drop/`flush()`) instead of wall-clock times, so LRU eviction is deterministic. Edits plug in through a `ThumbRequest::with_edits(hash, &EditFn)` hook until the M5 pipeline exists; unedited requests decode directly at thumbnail size via DCT scaling.
- M5.1: Edit model lives in `lb-core::edit` (not lb-imaging) so lb-catalog, lb-app and lb-ui can use the types without depending on the pixel code; lb-imaging implements the math against them. `EditOp::validate()` returns a sanitised copy: ranges are clamped, but NaN/inf, zero-area/out-of-bounds crops and regions, `RotateQuarter` turns outside {-2,-1,1,2}, and empty or >64-entry region/spot lists are rejected. `RetouchSpot { src_x, src_y, dst_x, dst_y, radius }` (radius normalised to the long edge, clamped 0.001..0.5) and `NormRect { x, y, w, h }` were not specified in detail. `EditStack::cache_hash()` is empty for an unedited stack, matching how lb-thumbs keys unedited photos. proptest strategies are exported from lb-core behind the `test-strategies` feature to avoid a lb-core <-> lb-testkit cycle.
- M5.2: Added `rand_pcg =0.10.2` and `rand_core =0.10.1` (FilmGrain, SPEC 6.6.3). Pixel ops are rayon-parallel over rows; each pixel/row is independent so results are bit-identical regardless of scheduling. Crate-level allow of `clippy::chunks_exact_to_as_chunks` in lb-imaging (our chunk size is always the constant 4 but the suggested `as_chunks` form does not compose with rayon rows).
